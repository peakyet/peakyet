Discrete-time
optimal control.

How do you choose what to do now, when that choice changes what you can do later?

We will answer that question with one small system, a pencil-and-paper calculation, and a lab you can change yourself. No previous control theory is assumed.

Prerequisites: basic algebra; derivatives introduced where needed; matrices only in Part III.
Reading path: 45–60 minutes for Parts I–II; another 30–45 minutes for the extensions.

00 / BEFORE THE SYMBOLS

Start with a thermostat, not a theorem.

A thermostat can turn the heater on when a room is cold. That is feedback control: measure the present situation and react. But suppose electricity will become expensive in an hour. Should you heat the room a little extra now? You need to predict the future, compare alternatives, and account for comfort and energy.

Optimal control is optimization over the evolution of a system. Your decisions are connected through time. An action that looks cheap now can leave an expensive problem later.

The lesson in one sentence: predict what an action does, charge for the action and its consequences, then choose the best tradeoff—and use fresh measurements when reality differs from the prediction.

Here “discrete” means discrete time: decisions happen at steps 0, 1, 2, … . States and actions can still be real numbers. Choosing a real-valued motor voltage each 10 ms is discrete-time control; choosing only “on” or “off” introduces a separate, discrete-action restriction.

Three passes, not one marathon

  1. Understand: read Sections 1–4 and reproduce the two-step example.
  2. Generalize: read Sections 5–7, then change one slider at a time.
  3. Connect: use Sections 8–11 when you are ready for matrices, numerical optimization, and stability.

At each “pause,” try answering before opening the explanation. Recognition is easier than understanding; predicting an answer is a better test.

01 / DESCRIBE WHAT CAN HAPPEN

State + action → next state.

Imagine a point on a line. Its target is the origin. At every step, you choose a displacement. If the current position is \(x_k\) and your chosen displacement is \(u_k\), then

\[x_{k+1} = x_k + u_k\]Current position + commanded movement = next position.

Start at \(x_0 = 2\). Choosing \(u_0 = -0.5\) moves you to \(x_1 = 1.5\). Choosing \(u_1 = -1\) next moves you to \(x_2 = 0.5\). A negative action moves left; it is not a “negative cost.”

NameSymbolMeaning
Time index\(k\)Which decision step we are at.
State\(x_k\)Information needed now to predict the next state, given an action.
Control / action / input\(u_k\)What we choose at step \(k\).
Dynamics\(x_{k+1} = f_k(x_k, u_k)\)The model linking one step to the next.
Horizon\(N\)Number of decisions: \(u_0, \ldots, u_{N-1}\); the last state is \(x_N\).

The point model is deliberately simple. A car usually needs position and velocity as its state: the same position with a different velocity leads to a different future. A state is a predictive summary, not necessarily just “where you are.”

Where does a discrete-time model come from?

If a velocity command \(v_k\) is held constant for a sampling interval \(\Delta t\), then \(x_{k+1} = x_k + \Delta t\,v_k\) exactly for an ideal velocity-controlled point. Our action is the increment \(u_k = \Delta t\,v_k\). For a force-controlled robot, the dynamics are different. Do not borrow a controller without checking its model and units.

Pause: if a moving car’s state contains only position, what is missing?

Velocity. Two cars at the same position, one parked and one moving fast, do not have the same next position under the same acceleration. Position alone is not a sufficient state for that model.

02 / SAY WHAT “BETTER” MEANS

Optimal with respect to what?

Going to the origin immediately seems obvious: choose \(u_0 = -x_0\). But a big action might use energy, stress a motor, or feel uncomfortable. We need a score that expresses the tradeoff.

\[J = \sum_{k=0}^{N-1} \left(qx_k^2 + ru_k^2\right) + sx_N^2\]\(q \ge 0\): position penalty · \(r > 0\): action penalty · \(s \ge 0\): final-position penalty.
  • Stage cost: \(qx_k^2 + ru_k^2\) charges for each decision step.
  • Terminal cost: \(sx_N^2\) charges for where you end up, after the final action.
  • Total cost: add every charge. Smaller is better. The square penalizes left and right errors equally and makes large deviations expensive.

For a nonzero target, define an error \(e_k = x_k - x_{\mathrm{target}}\). For our integrator with a constant target, \(e_{k+1} = e_k + u_k\), so the same derivation applies to the error.

A penalty is not a promise. A large terminal penalty encourages ending near zero. It does not enforce \(x_N = 0\). A hard terminal requirement must be written as a constraint, and it might be impossible to satisfy.

The general finite-horizon problem

\[\begin{aligned} \underset{u_0,\ldots,u_{N-1}}{\operatorname{minimize}}\quad & J = \sum_{k=0}^{N-1}\ell_k(x_k,u_k)+\varphi(x_N) \\ \text{subject to}\quad & x_{k+1}=f_k(x_k,u_k),\qquad x_0\text{ given}. \end{aligned}\]Optional constraints: \(x_k\in\mathcal X_k\), \(u_k\in\mathcal U_k\), \(x_N\in\mathcal X_N\).

We choose the actions; the dynamics determine the states. You may also optimize over states as explicit variables, but then the dynamics must hold as equality constraints.

Weights encode preferences, not universal truths. Since position and input can have different units, their weights must make the terms comparable. Multiplying all cost terms by the same positive constant leaves the minimizing actions unchanged.

03 / YOUR FIRST COMPLETE SOLUTION

Two decisions. No black box.

Use \(x_0 = 2\), \(N = 2\), and \(q = r = s = 1\). Our score is

\[J = x_0^2 + u_0^2 + x_1^2 + u_1^2 + x_2^2.\]

Start with the last action. If you arrive at an arbitrary state \(x_1\), its remaining action-dependent cost is \(u_1^2 + (x_1 + u_1)^2\). Complete the square:

\[\begin{aligned} & u_1^2 + (x_1 + u_1)^2 \\ &\quad = 2\left(u_1 + \frac{x_1}{2}\right)^2 + \frac{x_1^2}{2}. \end{aligned}\]

A square cannot be negative. Its smallest value is zero, achieved at \(u_1^* = -x_1/2\). Including the state cost \(x_1^2\), the best possible remaining cost is \(\frac{3}{2}x_1^2\).

Now go back one step. Because \(x_1 = 2 + u_0\), choose \(u_0\) to minimize

\[\begin{aligned} & 4 + u_0^2 + \frac{3}{2}(2 + u_0)^2 \\ &\quad = \frac{5}{2}\left(u_0 + \frac{6}{5}\right)^2 + \frac{32}{5}. \end{aligned}\]

Therefore \(u_0^* = -6/5 = -1.2\). This gives \(x_1 = 0.8\), then \(u_1^* = -0.4\) and \(x_2 = 0.4\). The point does not finish at zero: making the final correction costs more than it saves under these weights.

What you just discovered: replace “all the future decisions” by their best attainable cost as a function of the state. That is the central trick of dynamic programming.

Pause: why is the initial cost 4 included if it cannot change our decision?

It belongs to the specified total score. Since the initial state is fixed, that term is constant with respect to every action. Removing it changes the reported cost from 6.4 to 2.4, but not the optimal actions.

04 / REACT TO THE STATE YOU ACTUALLY HAVE

A sequence is a plan. A policy is a rule.

Our nominal plan was (−1.2, −0.4). But our derivation found something more useful: \(u_1^* = -x_1/2\) for any state at the last step. Repeating the first-step derivation with a symbolic initial state gives

\[\pi_0(x) = -0.6x,\qquad \pi_1(x) = -0.5x\]A policy \(\pi\) maps the current state to an action. The rule can depend on time.

Suppose a push adds +1 after the first movement. Instead of arriving at 0.8, you arrive at 1.8.

  • Open loop: execute the old second action −0.4. You end at 1.4.
  • Feedback: measure 1.8, then choose −0.5 × 1.8 = −0.9. You end at 0.9.

The feedback action minimizes the remaining cost from the state actually reached, assuming no further push. It cannot undo the cost already incurred. It does not need to know the first push in advance.

Feedback is not clairvoyance. A deterministic optimal policy is optimal for its modeled future. It is not automatically optimal against arbitrary unknown disturbances. Stochastic and robust control explicitly model uncertainty in different ways.

05 / THE GENERAL PRINCIPLE

Think backward. Then act forward.

Define the value function \(V_k(x)\): the smallest remaining cost if you start at state \(x\) at time \(k\) and behave optimally from then on. This is a function over possible states, not just a number along one trajectory.

At time \(N\), no actions remain. You only pay the terminal charge. One step earlier, try an action, pay its immediate cost, and add the best possible cost from the state it produces:

\[\begin{aligned} V_N(x) &= \varphi(x), \\ V_k(x) &= \min_u\left\{\ell_k(x,u)+V_{k+1}\bigl(f_k(x,u)\bigr)\right\}. \end{aligned}\]Bellman’s recursion. Minimize over feasible actions; infeasible continuations can be assigned value \(+\infty\).

The minimum is a cost. The minimizing action, written “arg min,” is the policy \(\pi_k(x)\). These are different objects.

Why is this valid?

Fix your first action. It determines the next state. Any continuation worse than the best continuation from that next state can be replaced by a better one. Therefore an optimal plan must use an optimal continuation. Now compare all first actions. This proves the recursion under the assumed state model and additive cost, when the minima exist.

For our two-step example: \(V_2(x) = x^2\), \(V_1(x) = 1.5x^2\), and \(V_0(x) = 1.6x^2\). Evaluating at 2 gives 1.6 × 4 = 6.4.

Why not always use a big grid?

If a scalar state is represented by 100 grid points, storing a value function is easy. If there are 10 state coordinates with 100 points each, there are \(100^{10}\) grid states per time step. This is the curse of dimensionality. Bellman gives the structure of the solution; it does not guarantee a cheap numerical representation.

Pause: why is “minimize just today’s stage cost” usually wrong?

For our model, \(x_k\) is already fixed when choosing \(u_k\). Minimizing only \(qx_k^2 + ru_k^2\) chooses zero input forever. The future-value term is what makes moving worthwhile.

06 / WHEN THE VALUE FUNCTION HAS A SIMPLE SHAPE

Linear + quadratic = a tractable recursion.

Generalize the dynamics slightly to \(x_{k+1} = ax_k + bu_k\). The number \(a\) describes natural drift, and \(b\) describes input effectiveness. Assume unconstrained real-valued inputs and the quadratic cost from Section 2.

The terminal value is \(sx^2\). Suppose the next value function has the form \(V_{k+1}(x) = P_{k+1}x^2\). Write \(P\) for \(P_{k+1}\) temporarily. Bellman asks us to minimize

\[\begin{aligned} & qx^2 + ru^2 + P(ax + bu)^2 \\ &\quad = (q + a^2P)x^2 + 2abP xu + (r + b^2P)u^2. \end{aligned}\]

The coefficient of \(u^2\) is strictly positive because \(r > 0\) and \(P \ge 0\). So this is a bowl with one global minimum. A derivative is the slope of the cost as you vary the action; at the bottom of this smooth bowl, the slope is zero. Here the derivative with respect to \(u\) is \(2abP x + 2(r + b^2P)u\). Set it to zero:

\[u_k^* = -K_k x_k,\qquad K_k = \frac{abP_{k+1}}{r + b^2P_{k+1}}.\]

Substituting this minimizing action back into the cost gives another quadratic value function, with coefficient

\[P_k = q + a^2P_{k+1} - \frac{(abP_{k+1})^2}{r + b^2P_{k+1}},\qquad P_N = s.\]

This is the finite-horizon Riccati recursion. We did not merely guess the quadratic shape: the terminal value has that shape, and the recursion preserves it. Backward induction therefore proves the shape and the solution at every step.

LQR = linear quadratic regulator. “Linear” describes the dynamics, “quadratic” describes the cost, and “regulator” means driving deviations toward an equilibrium. The feedback is linear because minimizing a quadratic with linear dynamics produces a linear action rule.

A complete numerical recipe

# Inputs: real a, b; q ≥ 0, r > 0, s ≥ 0; horizon N
P[N] = s
for k = N-1 down to 0:
    d = r + b*b*P[k+1]
    K[k] = b*P[k+1]*a / d
    P[k] = q + a*a*P[k+1] - (a*b*P[k+1])**2 / d

# Now run forward. Use the measured state at each step.
for k = 0 to N-1:
    u = -K[k] * measured_state
    apply(u)
    # The plant evolves; measure again at the next step.

For our original integrator, \(a = b = 1\), the same update simplifies to \(P_k = q + rP_{k+1}/(r + P_{k+1})\). With two steps and unit weights, this gives \(P_2 = 1\), \(P_1 = 1.5\), \(P_0 = 1.6\), and gains 0.6, 0.5, exactly as before.

Pause: what if the terminal weight is zero?

The final gain is zero: there is no cost for the state reached after the last action, so a final nonzero action only adds effort cost. Earlier gains can still be nonzero because earlier actions affect states charged by later stage costs. If \(q = s = 0\), all gains are zero.

Four experiments that teach different things

  1. Raise \(r\) from 1 to 8. Predict the first action before you look. It becomes less aggressive because action is expensive. The total cost need not decrease: you changed the scoring rule. Do not compare costs under different weights as though they used the same ruler.
  2. Reset, then set the push to +2. Open loop continues with the old plan. Feedback re-evaluates actions using the displaced state. With no push, the trajectories coincide; their overlap is expected.
  3. Set \(a\) to 1.3. Errors grow naturally without input. Notice how the gain responds. The nominal zero-input cost shows what doing nothing would cost, though that trajectory is not plotted.
  4. Reset, then set \(q = 0\). Only effort and the final error matter. The controller can spread its correction over time. The gain sequence is not constant; the deadline matters.

The lab has no actuator limits, sensor errors, or model mismatch beyond the single push. Its feedback costs are realized scores, not a claim of optimality for a general disturbance process. For this single push, once step 2 is measured and no more pushes occur, the remaining feedback policy is the optimal continuation.

08 / OPTIONAL MATRIX EXTENSION

The same idea, several state coordinates.

Now let \(\mathbf{x}_k\) be an \(n\)-dimensional column vector and \(\mathbf{u}_k\) an \(m\)-dimensional input. A linear model has matrices \(A\) of size \(n\times n\) and \(B\) of size \(n\times m\):

\[\begin{aligned} \mathbf{x}_{k+1} &= A\mathbf{x}_k+B\mathbf{u}_k, \\ J &= \sum_{k=0}^{N-1}\left(\mathbf{x}_k^{\mathsf T}Q\mathbf{x}_k+\mathbf{u}_k^{\mathsf T}R\mathbf{u}_k\right)+\mathbf{x}_N^{\mathsf T}S\mathbf{x}_N. \end{aligned}\]

Superscript \(\mathsf T\) means transpose. The matrix expression \(\mathbf{x}^{\mathsf T}Q\mathbf{x}\) is a scalar weighted error. Require symmetric \(Q\), \(S\) positive semidefinite (nonnegative for every state) and \(R\) positive definite (strictly positive for every nonzero input).

The value function is \(V_k(\mathbf{x}) = \mathbf{x}^{\mathsf T}P_k\mathbf{x}\). The scalar derivation becomes:

\[\begin{aligned} P_N &= S, \\ K_k &= \left(R+B^{\mathsf T}P_{k+1}B\right)^{-1}B^{\mathsf T}P_{k+1}A, \\ P_k &= Q+A^{\mathsf T}P_{k+1}A-A^{\mathsf T}P_{k+1}BK_k, \\ \mathbf{u}_k^* &= -K_k\mathbf{x}_k. \end{aligned}\]

\(P_k\) is \(n\times n\); \(K_k\) is \(m\times n\). The inverse is mathematical notation: in numerical code, solve the linear system for \(K_k\) instead of explicitly forming an inverse. Use a reliable Riccati implementation for serious work.

A robot example: position and velocity

A unit-mass point with acceleration input held constant for \(\Delta t\) obeys the exact sampled model

\[\begin{aligned} p_{k+1} &= p_k + \Delta t\,v_k + \frac{1}{2}(\Delta t)^2 u_k, \\ v_{k+1} &= v_k + \Delta t\,u_k. \end{aligned}\]

With \(\mathbf{x} = [p,v]^{\mathsf T}\), these two equations specify \(A\) and \(B\). Feedback becomes \(u = -k_p p-k_v v\): react both to where you are and how fast you are moving. That is why a useful controller starts braking before it reaches the target.

Check sampling assumptions. Forward Euler would omit \(\frac{1}{2}(\Delta t)^2u_k\) from the position update. That is an approximation, not the same model. Likewise, discretizing continuous dynamics does not automatically give the exact discrete cost: integrating a continuous quadratic running cost can produce state–input cross terms.

09 / ANOTHER VIEW OF THE SAME OPTIMUM

Costates measure the price of state.

Dynamic programming considers all possible states. Another route computes necessary conditions along a candidate trajectory. Assume differentiable dynamics and costs, unconstrained inputs, and a fixed initial state. For column gradients, introduce a costate \(\boldsymbol{\lambda}_{k+1}\) for each dynamics constraint:

\[\begin{aligned} \mathcal L = \varphi(\mathbf{x}_N) + \sum_{k=0}^{N-1}\Bigl[&\ell_k(\mathbf{x}_k,\mathbf{u}_k) \\ &+\boldsymbol{\lambda}_{k+1}^{\mathsf T}\bigl(f_k(\mathbf{x}_k,\mathbf{u}_k)-\mathbf{x}_{k+1}\bigr)\Bigr]. \end{aligned}\]

Setting derivatives with respect to the free states and inputs to zero yields:

\[\begin{aligned} \boldsymbol{\lambda}_N &= \nabla\varphi(\mathbf{x}_N), \\ \boldsymbol{\lambda}_k &= \nabla_x\ell_k+(D_x f_k)^{\mathsf T}\boldsymbol{\lambda}_{k+1}, & k&=N-1,\ldots,1, \\ \mathbf 0 &= \nabla_u\ell_k+(D_u f_k)^{\mathsf T}\boldsymbol{\lambda}_{k+1}, & k&=0,\ldots,N-1. \end{aligned}\]All derivatives are evaluated on the candidate trajectory. The same backward formula can define \(\boldsymbol{\lambda}_0\), but \(\mathbf{x}_0\) is fixed, so it has no stationarity condition.

The Jacobian \(D_x f\) describes how changing the current state changes the next state. Multiplying by the future costate propagates a future cost sensitivity backward. Define the Hamiltonian

\[H_k(\mathbf{x},\mathbf{u},\boldsymbol{\lambda}_{k+1}) = \ell_k(\mathbf{x},\mathbf{u}) + \boldsymbol{\lambda}_{k+1}^{\mathsf T}f_k(\mathbf{x},\mathbf{u}).\]

These equations become \(\boldsymbol{\lambda}_k = \nabla_x H_k\) and \(\nabla_u H_k = \mathbf 0\).

Check it on the two-step calculation

Our states are (2, 0.8, 0.4). Since \(\varphi(x) = x^2\), \(\lambda_2 = 2\times0.4 = 0.8\). Then \(\lambda_1 = 2\times0.8 + 0.8 = 2.4\). The input conditions give \(2u_1 + \lambda_2 = -0.8 + 0.8 = 0\) and \(2u_0 + \lambda_1 = -2.4 + 2.4 = 0\).

When the value function is differentiable, the optimal costate is its gradient along the optimal trajectory. In LQR, \(\boldsymbol{\lambda}_k = 2P_k\mathbf{x}_k\). The factor 2 comes from our choice of cost without a \(\frac12\) prefactor.

Necessary does not mean sufficient. For a general nonlinear, nonconvex problem, zero gradients may describe a local minimum, maximum, or saddle. For the unconstrained LQR here, the reduced objective is a strictly convex quadratic in the input sequence, so its stationary point is the unique global minimizer.

A practical connection: backpropagation through time

For any proposed input sequence, simulate the states forward, set the terminal costate, and propagate it backward. Then \(\mathbf{g}_k = \nabla_u\ell_k+(D_u f_k)^{\mathsf T}\boldsymbol{\lambda}_{k+1}\) is the gradient of the total cost with respect to that action. An optimizer can use these gradients to improve the sequence. This is reverse-mode differentiation through the dynamics.

10 / WHEN REAL HARDWARE HAS LIMITS

Constraints change the solution. MPC changes when you solve.

Suppose our actuator allows only \(|u_k|\le0.5\). The first action −1.2 in the two-step example is illegal. The dynamics and constraints must be optimized together.

For that particular two-step, unit-weight problem, the constrained optimum is (−0.5, −0.5), giving states (2, 1.5, 1) and cost 4 + 0.25 + 2.25 + 0.25 + 1 = 7.75. To see why, the final optimal action is the unconstrained \(-x_1/2\) limited to the interval [−0.5, 0.5]; for every feasible first action, \(x_1\ge1.5\), so the last action is −0.5. The remaining cost decreases as the first action moves toward −0.5.

Do not generalize that coincidence. Clipping an unconstrained LQR command gives a feasible input but is not generally the constrained optimum: earlier decisions should anticipate future saturation and state limits. For a one-step scalar quadratic problem, projection onto an interval is exact; that special fact does not solve arbitrary multistep constrained problems.

Direct optimization: stack all the actions

For the integrator, \(x_k = x_0+\sum_{j=0}^{k-1}u_j\). Substitute these expressions into the objective. With \(\mathbf U=[u_0,\ldots,u_{N-1}]^{\mathsf T}\), the result is

\[\begin{aligned} \underset{\mathbf U}{\operatorname{minimize}}\quad & \frac12\mathbf U^{\mathsf T}H\mathbf U+\mathbf h^{\mathsf T}\mathbf U+c \\ \text{subject to}\quad & G\mathbf U\le\mathbf g. \end{aligned}\]

This is a quadratic program (QP) when dynamics are linear, costs quadratic, and constraints linear. \(H\) here is a Hessian matrix, not the Hamiltonian from Section 9. With positive input weights, it is positive definite after eliminating the states. A feasible problem has a unique minimizer. General nonlinear models lead instead to nonlinear programs, which can have local minima.

Model predictive control: solve, apply one action, repeat

  1. Measure or estimate the current state.
  2. Solve a finite-horizon optimal-control problem starting there.
  3. Apply only the first action.
  4. At the next sample, measure again, shift the horizon, and solve again.

This is MPC, also called receding-horizon control. Replanning makes an optimization algorithm act as a feedback controller. Constraints are a major reason to use it. With model mismatch, even a feasible predicted trajectory may miss real constraints; robust design, margins, and state estimation can matter.

In the finite-horizon LQR lab, the deadline is fixed and the remaining horizon shrinks; we compute the full time-dependent policy once. Standard fixed-length MPC instead moves its deadline forward each step. For unconstrained, time-invariant linear-quadratic MPC with the same horizon and terminal weight at every solve, each step uses the same first gain. Those are different timing conventions.

Pause: can the bounded two-step integrator reach exactly zero from \(x_0 = 2\)?

No. Two inputs of magnitude at most 0.5 can reduce position by at most 1. The smallest reachable final position is 1. Adding the constraint \(x_2 = 0\) makes this problem infeasible; an optimizer cannot override physics.

11 / REMOVE THE DEADLINE, CAREFULLY

Why a constant feedback gain sometimes appears.

For an infinite horizon, we minimize \(\sum_{k=0}^{\infty}(\mathbf{x}_k^{\mathsf T}Q\mathbf{x}_k+\mathbf{u}_k^{\mathsf T}R\mathbf{u}_k)\). With time-invariant dynamics and appropriate assumptions, the Riccati recursion approaches a constant matrix \(P\). The same update with \(P_k = P_{k+1} = P\) becomes the discrete algebraic Riccati equation (DARE).

For the scalar integrator with \(q = r = 1\):

\[\begin{aligned} P &= 1+P-\frac{P^2}{1+P} \\ \Longrightarrow\quad P^2-P-1 &= 0 \\ \Longrightarrow\quad P &= \frac{1+\sqrt5}{2}\approx1.618, \\ K &= \frac{P}{1+P}\approx0.618. \end{aligned}\]

The negative root is not a nonnegative value coefficient. With the positive root, the closed loop is \(x_{k+1}=(1-K)x_k\approx0.382x_k\). Its magnitude shrinks geometrically toward zero. This is asymptotic stability for this scalar system.

A standard sufficient set of assumptions for the general result is \(R\) positive definite, \(Q\) positive semidefinite, \((A,B)\) stabilizable, and \((A,Q^{1/2})\) detectable. Roughly: any mode that can fail to decay must be controllable by the inputs, and any mode invisible to the state penalty must already decay. Under these assumptions the stabilizing nonnegative Riccati solution gives a stable closed loop.

Finite-horizon optimality is not a stability certificate. A short horizon, missing terminal penalty, or ignored unstable state can produce poor or unstable repeated behavior. MPC stability and recursive feasibility need additional design and analysis; they do not follow just from solving each optimization accurately.

12 / RETRIEVAL PRACTICE

Can you rebuild the argument?

Try these without scrolling upward. A correct explanation in your own words matters more than memorizing a formula.

1. One step: \(x_0 = 3\), \(q = 1\), \(r = 2\), \(s = 4\). Find the optimal input and final state.

Minimize \(9+2u^2+4(3+u)^2\). Its derivative is \(4u+8(3+u)=12u+24\). Thus \(u^*=-2\) and \(x_1=1\). The total cost is 9 + 8 + 4 = 21. The current-state penalty does not affect the one-step action because the current state is fixed.

2. Two steps again: \(x_0 = -1\), \(q = r = s = 1\). What changes?

The same gains 0.6 and 0.5 apply. Actions are +0.6 and +0.2, giving states −1, −0.4, −0.2. The optimal cost is 1.6. Reversing the initial sign reverses the trajectory and inputs; the quadratic cost stays the same for the same magnitude.

3. Suppose \(b = 0\). Can a large controller gain rescue the system?

No. Actions do not affect the state at all: \(x_{k+1}=ax_k\). The optimal input is zero because effort only adds cost. If \(|a|\ge1\) and the state is penalized with \(q > 0\), the infinite-horizon cost diverges for a nonzero initial state. Controllability is a property of the plant, not something gain tuning can invent.

4. What is the difference between \(V_k(x)\), \(\pi_k(x)\), and an open-loop plan?

\(V_k(x)\) tells you the smallest remaining cost. \(\pi_k(x)\) tells you which action achieves it from that state. An open-loop plan is one sequence of actions for one initial condition and one predicted evolution; it does not specify how to react to different observed states.

5. If every cost weight is multiplied by 7, what happens to \(K\) and \(P\)?

The objective is multiplied by 7, so its minimizing policy and gains stay the same. The value coefficients \(P_k\) and optimal total cost are multiplied by 7. This is a useful implementation check.

6. Why does the Riccati recursion run backward but the plant run forward?

You must know the price of the next state before deciding how much input to spend getting there. Start with the known terminal price, propagate prices backward, then use the resulting gains to choose actions as the real system evolves forward.

7. For a one-step problem, let \(s\) tend to infinity. Does the input go to zero?

For the integrator, \(u^*=-sx/(r+s)\), so it approaches \(-x\): the optimizer prioritizes eliminating the terminal error. At any finite positive \(s\) with \(r > 0\) and \(x\ne0\), a nonzero final error remains. A hard input bound may prevent reaching zero even in the limit.
